# wardogs-ops

**言語 / Language**: 日本語(このページ)

WARDOGS のコミュニティサーバーを運営している人向けの、**ブラウザから使える運営パネル**です。サーバーの状態・接続中のプレイヤー・BAN 一覧を見て、kick / ban / BAN 解除 / 全体メッセージ / 個別メッセージ / マップ変更 / 試合終了 を実行できます。操作はすべて記録(操作ログ)されます。

- 動かす場所は **Cloudflare Workers の無料プラン**です。自分の PC やサーバーを常時動かす必要はありません。
- プログラミングの知識は要りません。この手順書のとおりに、画面上でボタンを押して値を入力していけば使えます。
- このパネルは非公式のツールです。WARDOGS の開発元・販売元とは関係ありません。RCON(後述)の仕様は公式の資料が見つかっておらず、**非公式の資料をもとに作っています**。サーバーのバージョンによっては一部の操作が使えないことがあります(使えない操作のボタンは自動で押せなくなります)。

> **試用段階です。** 画面と API は実装済みで、付属のモック RCON で動作確認しています。本物の WARDOGS サーバーでの確認はまだです(RCON の仕様が非公式資料ベースのため)。実サーバーで試した結果は Issue で共有してください。

## 用語

| 用語 | 意味 |
|---|---|
| RCON | ゲームサーバーを外から操作するための仕組み。WARDOGS では Web の API(HTTP)として提供されているとされます |
| GitHub | プログラムの置き場所(リポジトリ)を管理するサービス。無料アカウントで使えます |
| フォーク | 他人のリポジトリを自分の GitHub アカウントにコピーすること |
| Cloudflare | Web サービスを動かす基盤。このパネルは Cloudflare の **Workers**(プログラムを動かす機能)と **D1**(データベース。操作ログの保存先)を使います |
| 管理パスワード | このパネルにログインするためのパスワード。デプロイした後、パネルを最初に開いた画面で自分で決めて登録します([3 章](#3-初期設定管理パスワードの登録))。Cloudflare の画面で入力する必要はありません |
| workers.dev | Cloudflare が無料で割り当てる URL。`https://wardogs-ops.<あなたのアカウント名>.workers.dev` のような形になります。URL を知っている人は誰でもログイン画面を開けます |
| AllowedHosts | RCON に「接続してよい相手」を決める、ゲームサーバー側の設定。Cloudflare の接続元は固定されないため、このパネルでは絞れない可能性があります([4.2](#42-allowedhosts接続元の制限)) |
| TLS | 通信を暗号化する仕組み。`https://` で始まる URL がこれを使っています。RCON は暗号化されていない `http://` とされています |
| ServerSettings.ini | ゲームサーバーの設定ファイル。RCON を有効にするときに、この中の RCON の部分を書き換えます([4.1](#41-serversettingsini-の例)) |
| Build command | Cloudflare の画面に出る入力欄の名前。プログラムを「動かせる形に作る」ときに実行する命令を入れます([方法 B](#方法-b-フォークしてダッシュボードで取り込む)) |
| Deploy command | Cloudflare の画面に出る入力欄の名前。作ったものを Cloudflare に「公開する」ときに実行する命令を入れます([方法 B](#方法-b-フォークしてダッシュボードで取り込む)) |

## 0. 始める前に確認すること

1. **RCON のポートをインターネットに公開できるか**。このパネルは Cloudflare から直接あなたのゲームサーバーの RCON に接続します。サーバーを借りている会社(提供元)によっては、RCON のポートを外部に公開できない場合があります。その場合このパネルは使えません。提供元の管理画面やサポートで確認してください。
2. **RCON の接続先を「ホスト名」で指定できるか**。ホスト名は `rcon.example.com` のような、IP アドレス(`203.0.113.10` のような数字の並び)ではない名前のことです。Cloudflare Workers は **IP アドレスを直接指定した接続ができません**(Cloudflare 公式の既知の制限)。IP アドレスしか無い場合は [4.3](#43-ip-アドレスしか無い場合) を先に読んでください。
3. **GitHub と Cloudflare の無料アカウント**。Cloudflare のアカウントには必ず **2 段階認証**(ログイン時にパスワードに加えてスマートフォンのアプリなどで確認する仕組み)を設定してください。理由は次の節のとおりです。

### このパネルを使うときに知っておいてほしいこと(トレードオフ)

このパネルは「Cloudflare の画面でパスワードなどを入力しなくても使える」ことを優先しています。その代わりに、次のことを受け入れて使う仕組みです。

- **パスワードはすべて、あなたの Cloudflare アカウントの中のデータベース(D1)に保存されます。**
  - **管理パスワード**(ログイン用)は、元に戻せない形(ハッシュ。パスワードから計算した値で、そこから元のパスワードは分からない)で保存します。そのため **忘れたら誰にも復元できません**。登録し直す手順は [6.4](#64-パスワードを忘れた乗っ取られた) にあります。
  - **RCON パスワード**は暗号化して保存しますが、**暗号化の鍵(`instance_key`)も同じデータベースにあります**。つまり、あなたの Cloudflare アカウントに入れる人(アカウントを乗っ取った人を含む)は、RCON パスワードを取り出せます。暗号化は「データベースの中身を画面やファイルで見たときに、パスワードがそのまま見えない」ための対策で、乗っ取りへの対策ではありません。
  - だから **Cloudflare アカウントの 2 段階認証は必須** と考えてください。
- RCON のパスワードは「読み取り専用」と「操作用」に分かれていません。1 つのパスワードで kick・ban・設定の書き換えまでできます。そのパスワードを Cloudflare に預けて使う仕組みです。
- RCON の通信は暗号化されていない(平文の HTTP)とされています。インターネット上の経路でパスワードを読み取られる可能性はゼロではありません。**RCON のパスワードは長いランダムな文字列にし、定期的に変えてください。**
- `workers.dev` の URL は **誰でも開ける公開 URL** です。ログイン画面は誰にでも見えるので、**守りになるのはログイン用の管理パスワードだけ**です。**16 文字以上の推測されにくいパスワード**を使ってください(作り方は [1 章](#1-パスワードを-2-つ作る))。
- パネルの「ログアウト」は、手元の Cookie(ログイン状態の印)を消すだけです。盗まれた Cookie は最長 12 時間使えます。共有の PC で使ったときは、ログアウトに加えてパスワードを変えてください([6.3](#63-パスワードを変える))。
- RCON の AllowedHosts(接続元の制限)で Cloudflare だけを許可する方法は、公式の資料からは見つかっていません。詳しくは [4.2](#42-allowedhosts接続元の制限)。

### デプロイ直後の「先に登録される」リスク

- 管理パスワードは、デプロイした後にパネルの画面([3 章](#3-初期設定管理パスワードの登録))で登録します。登録できるのは **最初の 1 人だけ** です。
- 登録するまでの間は、**URL を知っている人なら誰でも先に登録できてしまいます**(`workers.dev` の URL はアカウント名から推測され得ます)。
- 対策は 2 つです。
  1. **デプロイしたら、すぐにパネルを開いて登録する。**
  2. 開いたときに「管理パスワードを決める」画面ではなく **ログイン画面が出た場合は、自分以外の誰かが先に登録した可能性があります**。そのまま使わず、[6.4](#64-パスワードを忘れた乗っ取られた) の手順でデータベースの `admins` テーブルの行を消して、登録し直してください。
- 登録すると、操作ログの「設定変更」タブに「管理パスワード登録」の記録が残ります。身に覚えのない記録が無いか、ときどき確認してください。

## 1. パスワードを 2 つ作る

このパネルでは 2 つのパスワードを使います。**別々の値**にしてください(同じ値は登録できません)。

| 名前 | 用途 | 長さ |
|---|---|---|
| 管理パスワード | パネルにログインするためのパスワード。[3 章](#3-初期設定管理パスワードの登録)でパネルの画面に登録します | **16 文字以上が必須**(推奨: ランダムな 24 文字以上)。短いと登録できません |
| RCON パスワード | ゲームサーバーの RCON のパスワード。ゲームサーバーの設定([4.1](#41-serversettingsini-の例))と、パネルの「サーバー設定」([4.4](#44-パネルにサーバーを追加する画面から))の両方に同じ値を入れます | 推奨: ランダムな 32 文字以上 |

作り方(どれか 1 つ):

- **パスワード管理ソフト**(1Password、Bitwarden、ブラウザ内蔵のパスワード生成など)で「ランダム・32 文字・英数字のみ」を生成する。いちばん簡単です。
- **Windows**: スタートメニューで「PowerShell」を開き、次を貼り付けて Enter。48 文字の英数字が表示されます。

  ```powershell
  $b = New-Object byte[] 24; [Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($b); -join ($b | ForEach-Object { $_.ToString('x2') })
  ```

- **Mac**: 「ターミナル」を開き、`openssl rand -hex 24` を貼り付けて Enter。

記号(`=` `#` `"` など)はゲームの設定ファイルで問題を起こすことがあるため、**英数字だけ**にするのが安全です。作ったパスワードはパスワード管理ソフトなど安全な場所に保管してください。ほかのサービスで使っているパスワードの使い回しはしないでください。

## 2. Cloudflare にデプロイする

デプロイ = プログラムを Cloudflare 上で動く状態にすることです。方法は 2 つあります。

| | 方法 A: Deploy ボタン | 方法 B: フォーク + 取り込み |
|---|---|---|
| 手間 | 最小(ボタン 1 つ) | 少し多い |
| あとからの更新 | 手作業が必要になる可能性あり(要確認) | GitHub の「Sync fork」ボタンで済む |
| おすすめ | まず試したい人 | 長く使う人 |

### 方法 A: Deploy to Cloudflare ボタン

1. 下のボタンを押します。

   [![Deploy to Cloudflare](https://deploy.workers.cloudflare.com/button)](https://deploy.workers.cloudflare.com/?url=https://github.com/webya-jp/wardogs-ops.gmkz.jp)

   (ボタンの URL の書式: `https://deploy.workers.cloudflare.com/?url=<このリポジトリの URL>`)
2. Cloudflare にログインし、GitHub との連携を許可します。Cloudflare があなたの GitHub アカウントにこのリポジトリのコピーを作ります。
3. 設定画面が出ます。
   - **Worker の名前**: `wardogs-ops` のままにしてください(変えると自動更新が失敗することがあります。要確認)。
   - **D1 データベース**: 既定の名前のままで構いません。
   - パスワードなどを入力する欄はありません(パスワードはデプロイの後にパネルの画面で登録します)。
4. 「デプロイ」を押し、完了するまで数分待ちます。完了画面に表示された URL を控えておきます。

### 方法 B: フォークしてダッシュボードで取り込む

1. GitHub でこのリポジトリ(`https://github.com/webya-jp/wardogs-ops.gmkz.jp`)を開き、右上の **Fork** を押して自分のアカウントにフォークします。リポジトリは **公開(Public)のまま** で構いません(秘密の値はリポジトリに入れません)。
2. Cloudflare のダッシュボードで **Workers & Pages** → **Create application** → **Import a repository** を選び、フォークしたリポジトリを選びます。
3. 設定(ビルド設定の中に、次の入力欄が出ます)。下の「Build command」などは **Cloudflare の画面に出る入力欄の名前** です。画面の英語の項目名をそのまま探して、右の値を入力します。
   - Project name(Worker の名前): `wardogs-ops`(`wrangler.jsonc` の `name` と同じにする必要があります)
   - Build command: `pnpm build`
   - Deploy command: `pnpm run deploy`(`pnpm deploy` ではなく `run` を付けてください)
4. デプロイが終わるまで待ちます。パスワードなどを Cloudflare の画面で入力する必要はありません。

どちらの方法でも、パネルのデータ(管理パスワード・サーバー設定・操作ログ)を保存する D1 データベース(`wardogs-ops-db`)は初回デプロイ時に自動で作られます。**デプロイが終わったら、すぐに [3 章](#3-初期設定管理パスワードの登録) に進んでください。**

## 3. 初期設定(管理パスワードの登録)

デプロイしたら、ほかの作業より先にこの章を済ませてください([0 章](#デプロイ直後の先に登録されるリスク)の「先に登録される」リスクのため)。

1. デプロイ完了画面に表示された URL(`https://wardogs-ops.<アカウント名>.workers.dev`)をブラウザで開きます。
2. **「初期設定 / 管理パスワードを決める」** の画面が出ます(URL の末尾が `/setup` になります)。
   - ここでログイン画面が出た場合は、自分以外の誰かが先に登録した可能性があります。[6.4](#64-パスワードを忘れた乗っ取られた) へ進んでください。
3. **「管理パスワード」** と **「管理パスワード(確認のためもう一度)」** の 2 つの欄に、[1 章](#1-パスワードを-2-つ作る)で作った管理パスワードを同じように入力します。
   - **16 文字以上**が必要です(256 文字まで)。ランダムな 24 文字以上をおすすめします。
   - RCON パスワードと同じ値は使えません。
4. **「登録する」** を押します。
5. ログイン画面に切り替わり、「管理パスワードを登録しました。登録したパスワードでログインしてください。」と表示されます。登録したパスワードでログインします。「操作者名(任意)」は、複数人で使う場合に操作ログに誰が操作したかを残すための名前です(空欄でも構いません)。
6. 続けて [4 章](#4-ゲームサーバー側で-rcon-を有効にする) でゲームサーバーの RCON を有効にし、[4.4](#44-パネルにサーバーを追加する画面から) でパネルにサーバーを追加します。

登録したパスワードは、あとから画面で確認することはできません。パスワード管理ソフトなどに保管してください。

登録の画面に出るメッセージと対処:

| 表示 | 意味 | 対処 |
|---|---|---|
| 管理パスワードは 16 文字以上にしてください。 | 短すぎる | 長いパスワードにして入力し直す(入力欄は空に戻ります) |
| 確認のために入力したパスワードが一致しません。 | 2 つの欄の値が違う | 2 つの欄に同じ値を入力し直す |
| 登録済みのサーバーの RCON パスワードと同じ値は使えません。 | 登録し直しのときに、保存済みの RCON パスワードと同じ値を入れた | 別の値にする |
| 管理パスワードは既に登録されています。 | 先に登録が済んでいる(2 回押した場合も含む) | 「ログイン画面へ」を押してログインする。自分で登録した覚えが無い場合は [6.4](#64-パスワードを忘れた乗っ取られた) |
| データベース(D1)が見つかりません / 準備(マイグレーション)が済んでいません | データベースが作られていない・初期化されていない | [6.5](#65-データベースd1が使えないと表示される) を参照 |

## 4. ゲームサーバー側で RCON を有効にする

> ここに書いた設定項目は **非公式資料にもとづくもので、実際のサーバーでは確認できていません**。サーバーのバージョンや提供元によって異なる場合があります。分からない場合は提供元のサポートに「RCON を外部から接続できるようにしたい」と問い合わせてください。

### 4.1 ServerSettings.ini の例

`ServerSettings.ini` の `[/Script/WDRCON.WDRCONSettings]` の部分を次のようにします(非公式資料の記載例)。

```ini
[/Script/WDRCON.WDRCONSettings]
; RCON を有効にする
bEnabled=True
; ポート番号(既定 7776 とされていますが、提供元の管理画面で別の番号が割り当てられていることがあります)。パネルの「サーバー設定」のポートと合わせる
Port=7776
; 外部から接続できるようにする(既定はサーバー自身からのみ)
BindAddress=0.0.0.0
; パスワード。平文の Password= より、ハッシュ化した PasswordHash= を推奨
PasswordHash=<WardogsServer -GenerateRCONHash=<RCON パスワード> で生成した値>
```

- `BindAddress=0.0.0.0` にするには TLS(暗号化)と `PasswordHash` が必要、という非公式の記述があります。真偽は未確認です。
- `PasswordHash` はサーバーのプログラムに `-GenerateRCONHash=<パスワード>` を付けて実行すると作れるとされています。作れない場合は `Password=<RCON パスワード>` で設定します。
- ゲーム側の RCON パスワードと、パネルの「サーバー設定」([4.4](#44-パネルにサーバーを追加する画面から))に入れる RCON パスワードを **同じ値** にしてください。
- 設定後はゲームサーバーを再起動します。
- サーバー提供元の管理画面で、RCON のポート(例 7776)を外部に開放する設定が必要な場合があります。

### 4.2 AllowedHosts(接続元の制限)

AllowedHosts は「RCON に接続してよい相手」を制限する設定です(設定があることはパッチノートで確認できますが、書き方は未確認です)。

**Cloudflare Workers がどの IP アドレスから接続してくるかは公開されておらず、固定もされません**。そのため、AllowedHosts で「Cloudflare だけ許可」と書く方法はありません。このパネルを使う場合は、AllowedHosts で制限をかけない(全許可にする)必要がある可能性が高いです。全許可の書き方(空欄にする等)と、空欄のときに全許可になるのか全拒否になるのかは未確認です。

AllowedHosts で守れない分、次の対策を必ず行ってください。

- RCON パスワードをランダムな 32 文字以上にする
- `PasswordHash` を使い、設定ファイルに平文のパスワードを残さない
- パスワードを定期的に変える([6.3](#63-パスワードを変える))
- 将来、RCON が暗号化(TLS)に対応・確認できたら `https://` に切り替える

### 4.3 IP アドレスしか無い場合

Cloudflare Workers は IP アドレスを直接指定して接続できません。**ホスト名(ドメイン名)が必要です**。次のどれかを使います。上ほどおすすめです。

1. **サーバー提供元がホスト名をくれていないか確認する**。管理画面に `xxxx.<提供元のドメイン>` のような接続先が表示されていることがあります。
2. **自分のドメインを持っている場合**: DNS に A レコードを 1 つ追加します(例: 名前 `rcon`、値 = サーバーの IP アドレス)。パネルの「サーバー設定」のホスト名は `rcon.<あなたのドメイン>` になります。
   - ドメインを Cloudflare で管理している場合は、そのレコードの **プロキシ状態を「DNS のみ(灰色の雲)」** にしてください。オレンジ色の雲(プロキシ)だと 7776 番ポートに届きません。
3. **ドメインが無い場合**: 無料のダイナミック DNS サービスや、IP アドレスをホスト名に埋め込んで解決するタイプの DNS サービスを使う方法があります。ただし第三者のサービスに依存すること、このパネルで実際に動くかを確認していないことに注意し、自己判断で使ってください。

パネルの「サーバー設定」には、ホスト名とポート番号を別々の欄に入力します([4.4](#44-パネルにサーバーを追加する画面から))。

### 4.4 パネルにサーバーを追加する(画面から)

パネルにログインし、メニューの「サーバー設定」から、**表示名・ホスト名・ポート・RCON パスワード** の 4 つを入力するだけでサーバーを追加できます。Cloudflare の画面で設定する必要はありません。持っているサーバーの数だけ(最大 20 台)追加でき、画面上部のメニューで操作するサーバーを切り替えます。入力した RCON パスワードは暗号化して保存され、保存後は画面に表示されません(保存場所の注意は [0 章](#このパネルを使うときに知っておいてほしいこと))。

#### 追加する手順

1. パネルにログインします([5 章](#5-動作確認))。
2. 上のメニューの **「サーバー設定」** を押します。
3. **「サーバーを追加」** を押すと、入力欄が 4 つ出ます。
   - **表示名**: パネルの中で見分けるための名前(32 文字まで)。例: `メイン`、`イベント用`。ゲーム内のサーバー名と同じでなくて構いません。
   - **ホスト名**: RCON の接続先のホスト名(ドメイン名)だけを入力します。`http://` や `:7776` のようなポート番号は付けません。例: `rcon.example.com`
   - **ポート**: RCON のポート番号。サーバー提供元の管理画面に書かれている番号です(7776 とは限りません)。
   - **RCON パスワード**: ゲームサーバーの RCON に設定したパスワード(4.1 と同じ値)。ログイン用の管理パスワードと同じ値は使えません。
4. **「保存する」** を押します。保存すると、その場で接続テストを行い、結果が画面の上に出ます。
   - 「接続できました」: ゲーム内のサーバー名と人数が表示されます。これで使えます。
   - 「接続できませんでした」: 理由と対処が表示されます(5 章の表も参考にしてください)。**設定は保存されています**。原因を直したら、一覧の **「接続テスト」** でもう一度確認できます。
5. 画面上部の **「操作するサーバー」** で、追加したサーバーを選びます(JavaScript が無効な場合は選んでから「切り替え」を押します)。状態・プレイヤー・BAN の各画面が、選んだサーバーの内容に切り替わります。

一覧では、サーバーごとに **編集**・**接続テスト**・**無効にする / 有効にする**・**削除** ができます。

- **無効にする**: 一時的に使わないサーバーを、設定を残したまま切り替えメニューから外します。
- **削除**: 確認画面で表示名をそのまま入力すると削除されます。保存した RCON パスワードも消えます。操作ログは残ります。

#### 注意

- **IP アドレスは入力できません**(Cloudflare Workers は IP アドレスを直接指定して接続できないため)。IP アドレスしか無い場合は、先に [4.3](#43-ip-アドレスしか無い場合) の方法でホスト名を用意してください。
- **ゲーム側の RCON パスワードを変えたとき**: 「サーバー設定」で該当サーバーの **「編集」** を開き、RCON パスワード欄に新しい値を入れて保存します(パスワード欄は、変えない場合は空欄のままにします)。
- **ホスト名かポートを変えるとき**: 安全のため、RCON パスワードも入れ直す必要があります(空欄のままだと「RCON パスワードも入力し直してください」と表示されます)。
- 管理パスワード(ログイン用)を登録し直しても、保存したサーバーと RCON パスワードはそのまま使えます。
- 操作ログの画面では「操作」と「設定変更」(サーバーの追加・変更・削除の記録)をタブで切り替えられます。「操作」はサーバーで絞り込めます。

## 5. 動作確認

1. デプロイ完了画面に表示された URL(`https://wardogs-ops.<アカウント名>.workers.dev`)をブラウザで開きます。
2. ログイン画面が出たら、3 章で登録した管理パスワードを入力します。「操作者名」は任意です(複数人で使う場合、操作ログに誰が操作したかを残すために入れます)。
3. [4.4](#44-パネルにサーバーを追加する画面から) でサーバーを追加し、状態画面にサーバー名・マップ・人数が表示されれば成功です。
4. 「設定の確認」の画面(`/setup`)が出て、データベースに関する案内が表示された場合は [6.5](#65-データベースd1が使えないと表示される) を見てください。
5. **本物の操作をする前に、操作ログに記録が残ることを確かめます。** 操作ログの画面を開いて今の行数を見てから、全体メッセージを 1 回送ります(プレイヤーに表示されます)。操作ログに行が 1 つ増えれば正常です。

表示されるエラーと対処:

| 表示 | 主な原因 | 対処 |
|---|---|---|
| RCON に接続できません | URL の間違い、ポートが開いていない、IP アドレスを指定している、DNS がプロキシ(オレンジの雲) | 「サーバー設定」のホスト名・ポート、4.1 のポート開放、4.3 を確認 |
| RCON の応答がありません | サーバーが停止中・再起動中、通信が遅い | 少し待って再読み込み |
| RCON の認証に失敗しました | パスワードが一致しない、AllowedHosts で拒否されている | ゲーム側と「サーバー設定」の RCON パスワードを同じ値に。4.2 を確認 |
| このサーバーでは使えない操作です | サーバーのバージョンにその機能が無い | ボタンは自動で無効になります |
| データベース(D1)が見つかりません / 準備が済んでいません | D1 データベースが作られていない・初期化されていない | 6.5 を参照 |

## 6. 更新と困ったとき

### 6.1 更新する(方法 B: フォークの場合)

1. GitHub で自分のフォークを開き、**Sync fork** → **Update branch** を押します。
2. Cloudflare が自動で再デプロイします(Workers Builds)。管理パスワード・サーバー設定・操作ログはそのまま残ります。

### 6.2 更新する(方法 A: ボタンの場合)

ボタンで作られたリポジトリは、元のリポジトリの「フォーク」にならない可能性があり、その場合は Sync fork が使えません(要確認)。そのときは、元のリポジトリの変更を自分のリポジトリに反映する作業が必要です。難しい場合は、方法 B で作り直すのが簡単です(管理パスワードの登録とサーバーの追加をやり直します。操作ログは引き継げません)。

### 6.3 パスワードを変える

- **管理パスワード(ログイン用)**: パネル上の変更画面はまだありません(今後追加予定)。今は [6.4](#64-パスワードを忘れた乗っ取られた) と同じ手順(登録を消して登録し直す)で変えます。登録し直すと全員がログアウトされます。サーバー設定と操作ログは残ります。ログアウトは手元の Cookie を消すだけで、盗まれた Cookie は最長 12 時間有効です。共有の PC で使ったときは、ログアウトに加えてこの変更も行ってください。
- **RCON パスワード**: 先にゲームサーバーの設定を変えて再起動し、すぐにパネルの「サーバー設定」で該当サーバーを「編集」して新しい値を入れます。その間はパネルから RCON に接続できません。パスワードが漏れた疑いがあるときは最優先で行ってください。

### 6.4 パスワードを忘れた・乗っ取られた

管理パスワードを忘れたとき、誰かに知られた・先に登録されたときは、Cloudflare のデータベースから **管理者の登録(`admins` テーブルの行)だけ** を消して、登録し直します。管理パスワードはハッシュで保存しているため、元のパスワードを調べる方法はありません。

1. Cloudflare のダッシュボードにログインし、左のメニューの **Storage & Databases → D1** を開きます。
2. 一覧から **`wardogs-ops-db`** を選びます。
3. **`admins` テーブルの行を削除します。** 画面の構成は Cloudflare の更新で変わることがあるため(要確認)、次のどちらかの方法で行ってください。
   - テーブルの一覧から `admins` を開き、表示された行を選んで削除する。
   - SQL を入力できる欄(Console など)がある場合は、`DELETE FROM admins;` と入力して実行する。
   - **ほかのテーブル(特に `settings`)は消さないでください。** `settings` には RCON パスワードの暗号化の鍵(`instance_key`)が入っています。消すと全員がログアウトされ、保存した RCON パスワードが読めなくなります(サーバー設定で入れ直せば直ります)。
4. **すぐに** パネルの URL を開きます。「管理パスワードを決める」の画面が出るので、[3 章](#3-初期設定管理パスワードの登録) の手順で新しい管理パスワードを登録します(行を消してから登録するまでの間は、誰でも登録できてしまうため)。
5. ログインし直します。`instance_key` は残っているので、**登録したサーバーと操作ログはそのまま使えます**。古いパスワードでのログイン状態はすべて無効になります。
6. 乗っ取られた疑いがある場合は、各サーバーの RCON パスワードも変えてください([6.3](#63-パスワードを変える))。操作ログの「設定変更」タブで、身に覚えのない登録・変更が無いかも確認します。

開発者向けの補足: コマンドで行う場合は、このリポジトリを手元に用意して Cloudflare にログイン(`pnpm wrangler login`)したうえで、`pnpm wrangler d1 execute wardogs-ops-db --remote --command "DELETE FROM admins;"` を実行します。`DELETE FROM settings` は実行しないでください。

### 6.5 データベース(D1)が使えないと表示される

パネルを開いたときに「設定の確認」の画面が出て、「データベース(D1)が見つかりません」または「データベース(D1)の準備(マイグレーション)が済んでいません」と表示される場合です。マイグレーションは、データベースに必要な表を作る初期化の作業のことです。

- Cloudflare のダッシュボードの **Storage & Databases → D1** に `wardogs-ops-db` があるか確認します。
- 方法 B の場合は Deploy command が `pnpm run deploy` になっているか確認し、再デプロイします(データベースの初期化は deploy の中で行います)。
- 直したら、パネルの画面を再読み込みします。
- データベースが使えない間は、パネルにログインできません(管理パスワードもサーバー設定もデータベースにあるため)。

### 6.6 その他

- ログイン画面で「ログインの失敗が続いたため、約 N 分間ログインできません」と出た: 同じ場所から 15 分に 5 回パスワードを間違えると 15 分ロックされます。
- 画面上部に「直近 1 時間にログインの失敗が多数あります」と出た: 誰かがパスワードを試している可能性があります。管理パスワードが推測されにくいものか確認し、心当たりが無ければ [6.3](#63-パスワードを変える) の手順で変えてください。
- 画面上部に「保存済みの RCON パスワードを読み出せないサーバーがあります」と出た: データベースの `settings` が消えた・変わった可能性があります。「サーバー設定」で該当サーバーを「編集」し、RCON パスワードを入れ直してください。
- 1 日の利用回数の上限(無料プランは 1 日 10 万リクエスト)に達すると、日本時間の朝 9 時まで止まります。画面は 30 秒ごとに自動更新され、裏に回したタブでは更新を止めるので、普通に使う分には上限に届きません。
- カスタムドメイン(例 `ops.example.com`)で使いたい場合は、`wrangler.jsonc` の `env` にある `gmkz`(作者の環境)のブロックをコピーしてキー名と `pattern` を自分のものに変え、`pnpm run deploy:env <キー名>` でデプロイします(Cloudflare でそのドメインを管理している必要があります)。この環境では `workers_dev` を `false` にしているので、入口はカスタムドメインだけになります。

## 開発者向け

- 設計: `docs/ARCHITECTURE.md`(構成・認証・要確認一覧)、`docs/API.md`(内部 API と RCON の対応)、`docs/PLAN.md`(企画)
- ビルド: `pnpm build`。型チェック: `pnpm check`。単体テスト: `pnpm test`
- 手動デプロイ: `pnpm build` → `pnpm run deploy`(`wrangler deploy` の後に D1 のマイグレーションを適用)
- API の確認記録: `docs/API_TEST.md`
- 任意の設定(`wrangler.jsonc` の `vars`。変えなくても動きます): `LANGUAGE`(画面の言語。既定 `ja`。現在は日本語のみ)、`TIMEZONE`(日時を表示するタイムゾーン。既定 `Asia/Tokyo`)

### ローカルで動かす(モック RCON を使う)

本物のゲームサーバーが無くても、付属のモック RCON(`scripts/mock-rcon.mjs`。架空のプレイヤーと BAN が入っている)で画面と API を試せます。`.dev.vars` などの秘密の設定ファイルは要りません(管理パスワードも RCON パスワードもローカルの D1 に入ります)。

1. `pnpm install`
2. `pnpm db:migrate:local`(ローカルの D1 に表を作る。初回だけ)
3. 端末を 2 つ開き、先にモック RCON を 2 台分(ポート 7776 と 7777)で起動します。
   - bash: `MOCK_RCON_PORTS=7776,7777 pnpm mock:rcon`
   - PowerShell: `$env:MOCK_RCON_PORTS='7776,7777'; pnpm mock:rcon`
   - パスワードは全ポート共通で、`scripts/mock-rcon.mjs` の先頭に書いてある公開のダミー値です(`MOCK_RCON_PASSWORD` で変えられます。ポートごとに変えるときは `MOCK_RCON_PASSWORDS` にカンマ区切りで同じ順に指定)。
4. もう 1 つの端末で `pnpm dev` を起動します。
5. ブラウザで `pnpm dev` が表示した URL を開くと `/setup` に移るので、管理パスワード(16 文字以上の任意の文字列。ローカル用で、本番と同じ値にしない)を登録してログインします。
6. 「サーバー設定」→「サーバーを追加」で 2 台を登録します。
   - 1 台目: 表示名は任意、ホスト名 `localhost`、ポート `7776`、RCON パスワードはモックのパスワード
   - 2 台目: 表示名は任意(1 台目と別の名前)、ホスト名 `localhost`、ポート `7777`、RCON パスワードは同上
   - `127.0.0.1` は IP アドレスのため登録できません。`localhost` と書きます。**本物のサーバーの RCON パスワードはローカル開発で使わないでください。**
7. 保存後の接続テストに `Mock Server 7776` / `Mock Server 7777` と出れば成功です。画面上部の「操作するサーバー」で切り替え、状態・プレイヤーの内容が変わることを確かめます。

ローカルの D1 を作り直す(初期設定からやり直したい、または以前の版の表で作ってしまった場合。**2026-10-16 にマイグレーション 0002 を書き換えたため、それ以前に `pnpm db:migrate:local` を実行した D1 は作り直しが必要**):

1. `pnpm dev` を止めます。
2. `.wrangler/state/v3/d1` を削除します(残しておきたい場合は別名に移します)。
3. `pnpm db:migrate:local` を実行し、`pnpm dev` を起動し直して `/setup` から登録します。

補足:

- モックは自分の PC の中(ループバック)だけで待ち受けます。ポートごとにサーバー名(`Mock Server <ポート>`)・プレイヤー・BAN が別々です。kick するとプレイヤー一覧から消え、ban すると BAN 一覧に増えます。モックを再起動すると元に戻ります(仕様は `scripts/mock-rcon.mjs` の先頭と `docs/ARCHITECTURE.md` 15.10)
- 開発時のログイン Cookie は `wo_session`(`Secure` なし)、本番は `__Host-wo_session` です。選んだサーバーは `wo_server`(本番は `__Host-wo_server`)に保存されます
