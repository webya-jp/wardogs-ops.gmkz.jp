# wardogs-ops

**言語 / Language**: 日本語(このページ)

WARDOGS のコミュニティサーバーを運営している人向けの、**ブラウザから使える運営パネル**です。サーバーの状態・接続中のプレイヤー・BAN 一覧を見て、kick / ban / BAN 解除 / 全体メッセージ / 個別メッセージ / マップ変更 / 試合終了 を実行できます。操作はすべて記録(操作ログ)されます。

- 動かす場所は **Cloudflare Workers の無料プラン**です。自分の PC やサーバーを常時動かす必要はありません。
- プログラミングの知識は要りません。この手順書のとおりに、画面上でボタンを押して値を入力していけば使えます。
- このパネルは非公式のツールです。WARDOGS の開発元・販売元とは関係ありません。RCON(後述)の仕様は公式の資料が見つかっておらず、**非公式の資料をもとに作っています**。サーバーのバージョンによっては一部の操作が使えないことがあります(使えない操作のボタンは自動で押せなくなります)。

> **試用段階です。** 画面と API は実装済みで、付属のモック RCON で動作確認しています。本物の WARDOGS サーバーでの確認はまだです(RCON の仕様が非公式資料ベースのため)。実サーバーで試した結果は Issue で共有してください。

## 用語

| 用語 | 意味 |
|---|---|
| RCON | ゲームサーバーを外から操作するための仕組み。WARDOGS では Web の API(HTTP)として提供されているとされます |
| GitHub | プログラムの置き場所(リポジトリ)を管理するサービス。無料アカウントで使えます |
| フォーク | 他人のリポジトリを自分の GitHub アカウントにコピーすること |
| Cloudflare | Web サービスを動かす基盤。このパネルは Cloudflare の **Workers**(プログラムを動かす機能)と **D1**(データベース。操作ログの保存先)を使います |
| Secret(シークレット) | パスワードのような秘密の設定値。Cloudflare に保存され、あとから画面で値を見ることはできません |
| workers.dev | Cloudflare が無料で割り当てる URL。`https://wardogs-ops.<あなたのアカウント名>.workers.dev` のような形になります。URL を知っている人は誰でもログイン画面を開けます |
| AllowedHosts | RCON に「接続してよい相手」を決める、ゲームサーバー側の設定。Cloudflare の接続元は固定されないため、このパネルでは絞れない可能性があります([4.2](#42-allowedhosts接続元の制限)) |
| TLS | 通信を暗号化する仕組み。`https://` で始まる URL がこれを使っています。RCON は暗号化されていない `http://` とされています |
| ServerSettings.ini | ゲームサーバーの設定ファイル。RCON を有効にするときに、この中の RCON の部分を書き換えます([4.1](#41-serversettingsini-の例)) |
| Build command | Cloudflare の画面に出る入力欄の名前。プログラムを「動かせる形に作る」ときに実行する命令を入れます([方法 B](#方法-b-フォークしてダッシュボードで取り込む)) |
| Deploy command | Cloudflare の画面に出る入力欄の名前。作ったものを Cloudflare に「公開する」ときに実行する命令を入れます([方法 B](#方法-b-フォークしてダッシュボードで取り込む)) |

## 0. 始める前に確認すること

1. **RCON のポートをインターネットに公開できるか**。このパネルは Cloudflare から直接あなたのゲームサーバーの RCON に接続します。サーバーを借りている会社(提供元)によっては、RCON のポートを外部に公開できない場合があります。その場合このパネルは使えません。提供元の管理画面やサポートで確認してください。
2. **RCON の接続先を「ホスト名」で指定できるか**。Cloudflare Workers は `http://203.0.113.10:7776` のような **IP アドレスの直接指定に接続できません**(Cloudflare 公式の既知の制限)。`http://rcon.example.com:7776` のようなホスト名が必要です。IP アドレスしか無い場合は [4.3](#43-ip-アドレスしか無い場合) を先に読んでください。
3. **GitHub と Cloudflare の無料アカウント**。Cloudflare のアカウントには必ず **2 段階認証** を設定してください(このパネルには RCON の全権パスワードを預けるため)。

### このパネルを使うときに知っておいてほしいこと

- RCON のパスワードは「読み取り専用」と「操作用」に分かれていません。1 つのパスワードで kick・ban・設定の書き換えまでできます。そのパスワードを Cloudflare に預けて使う仕組みです。
- RCON の通信は暗号化されていない(平文の HTTP)とされています。インターネット上の経路でパスワードを読み取られる可能性はゼロではありません。**RCON のパスワードは長いランダムな文字列にし、定期的に変えてください。**
- `workers.dev` の URL は **誰でも開ける公開 URL** です。ログイン画面は誰にでも見えるので、**守りになるのはログインパスワード(`ADMIN_PASSWORD`)だけ**です。**16 文字以上の推測されにくいパスワード**を使ってください(作り方は [1 章](#1-パスワードを-2-つ作る))。
- パネルの「ログアウト」は、手元の Cookie(ログイン状態の印)を消すだけです。盗まれた Cookie は最長 12 時間使えます。共有の PC で使ったときは、ログアウトに加えてパスワードを変えてください([6.3](#63-パスワードを変える))。
- RCON の AllowedHosts(接続元の制限)で Cloudflare だけを許可する方法は、公式の資料からは見つかっていません。詳しくは [4.2](#42-allowedhosts接続元の制限)。

## 1. パスワードを 2 つ作る

このパネルでは 2 つのパスワードを使います。**別々の値**にしてください。

| 名前 | 用途 | 長さ |
|---|---|---|
| `ADMIN_PASSWORD` | パネルにログインするためのパスワード | **16 文字以上が必須**(推奨: ランダムな 24 文字以上)。短いとログインできません |
| `RCON_PASSWORD` | ゲームサーバーの RCON のパスワード | 推奨: ランダムな 32 文字以上 |

作り方(どれか 1 つ):

- **パスワード管理ソフト**(1Password、Bitwarden、ブラウザ内蔵のパスワード生成など)で「ランダム・32 文字・英数字のみ」を生成する。いちばん簡単です。
- **Windows**: スタートメニューで「PowerShell」を開き、次を貼り付けて Enter。48 文字の英数字が表示されます。

  ```powershell
  $b = New-Object byte[] 24; [Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($b); -join ($b | ForEach-Object { $_.ToString('x2') })
  ```

- **Mac**: 「ターミナル」を開き、`openssl rand -hex 24` を貼り付けて Enter。

記号(`=` `#` `"` など)はゲームの設定ファイルで問題を起こすことがあるため、**英数字だけ**にするのが安全です。作ったパスワードはパスワード管理ソフトなど安全な場所に保管してください。

## 2. Cloudflare にデプロイする

デプロイ = プログラムを Cloudflare 上で動く状態にすることです。方法は 2 つあります。

| | 方法 A: Deploy ボタン | 方法 B: フォーク + 取り込み |
|---|---|---|
| 手間 | 最小(ボタン 1 つ) | 少し多い |
| あとからの更新 | 手作業が必要になる可能性あり(要確認) | GitHub の「Sync fork」ボタンで済む |
| おすすめ | まず試したい人 | 長く使う人 |

### 方法 A: Deploy to Cloudflare ボタン

1. 下のボタンを押します。

   [![Deploy to Cloudflare](https://deploy.workers.cloudflare.com/button)](https://deploy.workers.cloudflare.com/?url=https://github.com/webya-jp/wardogs-ops.gmkz.jp)

   (ボタンの URL の書式: `https://deploy.workers.cloudflare.com/?url=<このリポジトリの URL>`)
2. Cloudflare にログインし、GitHub との連携を許可します。Cloudflare があなたの GitHub アカウントにこのリポジトリのコピーを作ります。
3. 設定画面が出ます。
   - **Worker の名前**: `wardogs-ops` のままにしてください(変えると自動更新が失敗することがあります。要確認)。
   - **D1 データベース**: 既定の名前のままで構いません。
   - **Secrets**: `ADMIN_PASSWORD`、`RCON_URL`、`RCON_PASSWORD` の 3 つを入力します([3 章](#3-secrets-の意味))。
4. 「デプロイ」を押し、完了するまで数分待ちます。

### 方法 B: フォークしてダッシュボードで取り込む

1. GitHub でこのリポジトリ(`https://github.com/webya-jp/wardogs-ops.gmkz.jp`)を開き、右上の **Fork** を押して自分のアカウントにフォークします。リポジトリは **公開(Public)のまま** で構いません(秘密の値はリポジトリに入れません)。
2. Cloudflare のダッシュボードで **Workers & Pages** → **Create application** → **Import a repository** を選び、フォークしたリポジトリを選びます。
3. 設定(ビルド設定の中に、次の入力欄が出ます)。下の「Build command」などは **Cloudflare の画面に出る入力欄の名前** です。画面の英語の項目名をそのまま探して、右の値を入力します。
   - Project name(Worker の名前): `wardogs-ops`(`wrangler.jsonc` の `name` と同じにする必要があります)
   - Build command: `pnpm build`
   - Deploy command: `pnpm run deploy`(`pnpm deploy` ではなく `run` を付けてください)
4. デプロイが終わったら、**Workers & Pages → wardogs-ops → Settings → Variables and Secrets → Add** で、種類 **Secret** を選び、`ADMIN_PASSWORD`、`RCON_URL`、`RCON_PASSWORD` を 1 つずつ追加します。

どちらの方法でも、操作ログ用の D1 データベースは初回デプロイ時に自動で作られます。

## 3. Secrets の意味

| 名前 | 入れる値 | 例 |
|---|---|---|
| `ADMIN_PASSWORD` | 1 章で作ったログイン用パスワード(16 文字以上) | − |
| `RCON_URL` | RCON の接続先。`http://` + ホスト名 + `:` + ポート番号。末尾に `/` や `/v1` は付けない。ポート番号はサーバー提供元の管理画面に書かれている RCON のポート(提供元やサーバーごとに 7776 以外のこともある。例: 7779、7789)をそのまま書く | `http://rcon.example.com:7776` |
| `RCON_PASSWORD` | 1 章で作った RCON 用パスワード。4 章でゲームサーバーにも同じ値を設定します | − |

任意の設定(入れなくても動きます):

| 名前 | 内容 |
|---|---|
| `SESSION_SECRET` | ログイン状態の署名に使う鍵を、ログインパスワードとは別に持ちたい場合に設定(ランダム 32 文字以上)。設定すると安全性が少し上がります。追加・変更すると全員がログアウトされます |
| `AUDIT_REQUIRED` | 既定は `true`。操作ログ用のデータベースが使えないときは操作ボタンを止めます。`false` にするとログ無しでも操作できますが、おすすめしません(`wrangler.jsonc` の `vars` で変更) |
| 言語 / Language(`LANGUAGE`) | 画面の言語。既定は `ja`(日本語)。現在は日本語のみです(`wrangler.jsonc` の `vars` で変更) |
| タイムゾーン(`TIMEZONE`) | 日時を表示するタイムゾーン。既定は `Asia/Tokyo`(日本時間)(`wrangler.jsonc` の `vars` で変更) |

値はあとから **Settings → Variables and Secrets** で変更できます(値そのものは表示されません。変更は上書きで行います)。

## 4. ゲームサーバー側で RCON を有効にする

> ここに書いた設定項目は **非公式資料にもとづくもので、実際のサーバーでは確認できていません**。サーバーのバージョンや提供元によって異なる場合があります。分からない場合は提供元のサポートに「RCON を外部から接続できるようにしたい」と問い合わせてください。

### 4.1 ServerSettings.ini の例

`ServerSettings.ini` の `[/Script/WDRCON.WDRCONSettings]` の部分を次のようにします(非公式資料の記載例)。

```ini
[/Script/WDRCON.WDRCONSettings]
; RCON を有効にする
bEnabled=True
; ポート番号(既定 7776 とされていますが、提供元の管理画面で別の番号が割り当てられていることがあります)。RCON_URL のポートと合わせる
Port=7776
; 外部から接続できるようにする(既定はサーバー自身からのみ)
BindAddress=0.0.0.0
; パスワード。平文の Password= より、ハッシュ化した PasswordHash= を推奨
PasswordHash=<WardogsServer -GenerateRCONHash=<RCON_PASSWORD> で生成した値>
```

- `BindAddress=0.0.0.0` にするには TLS(暗号化)と `PasswordHash` が必要、という非公式の記述があります。真偽は未確認です。
- `PasswordHash` はサーバーのプログラムに `-GenerateRCONHash=<パスワード>` を付けて実行すると作れるとされています。作れない場合は `Password=<RCON_PASSWORD>` で設定します。
- ゲーム側の RCON パスワードと、Cloudflare に入れた `RCON_PASSWORD` を **同じ値** にしてください。
- 設定後はゲームサーバーを再起動します。
- サーバー提供元の管理画面で、RCON のポート(例 7776)を外部に開放する設定が必要な場合があります。

### 4.2 AllowedHosts(接続元の制限)

AllowedHosts は「RCON に接続してよい相手」を制限する設定です(設定があることはパッチノートで確認できますが、書き方は未確認です)。

**Cloudflare Workers がどの IP アドレスから接続してくるかは公開されておらず、固定もされません**。そのため、AllowedHosts で「Cloudflare だけ許可」と書く方法はありません。このパネルを使う場合は、AllowedHosts で制限をかけない(全許可にする)必要がある可能性が高いです。全許可の書き方(空欄にする等)と、空欄のときに全許可になるのか全拒否になるのかは未確認です。

AllowedHosts で守れない分、次の対策を必ず行ってください。

- `RCON_PASSWORD` をランダムな 32 文字以上にする
- `PasswordHash` を使い、設定ファイルに平文のパスワードを残さない
- パスワードを定期的に変える([6.3](#63-パスワードを変える))
- 将来、RCON が暗号化(TLS)に対応・確認できたら `https://` に切り替える

### 4.3 IP アドレスしか無い場合

Cloudflare Workers は IP アドレスを直接指定して接続できません。**ホスト名(ドメイン名)が必要です**。次のどれかを使います。上ほどおすすめです。

1. **サーバー提供元がホスト名をくれていないか確認する**。管理画面に `xxxx.<提供元のドメイン>` のような接続先が表示されていることがあります。
2. **自分のドメインを持っている場合**: DNS に A レコードを 1 つ追加します(例: 名前 `rcon`、値 = サーバーの IP アドレス)。`RCON_URL` は `http://rcon.<あなたのドメイン>:7776` になります。
   - ドメインを Cloudflare で管理している場合は、そのレコードの **プロキシ状態を「DNS のみ(灰色の雲)」** にしてください。オレンジ色の雲(プロキシ)だと 7776 番ポートに届きません。
3. **ドメインが無い場合**: 無料のダイナミック DNS サービスや、IP アドレスをホスト名に埋め込んで解決するタイプの DNS サービスを使う方法があります。ただし第三者のサービスに依存すること、このパネルで実際に動くかを確認していないことに注意し、自己判断で使ってください。

いずれも、ホスト名の後ろに `:ポート番号` を付け、先頭は `http://` です。

### 4.4 パネルにサーバーを追加する(画面から)

> **準備中です。** この節の機能はまだ実装されていません(設計は `docs/ARCHITECTURE.md` 第 15 章)。

パネルにログインし、メニューの「サーバー設定」から、**表示名・ホスト名・ポート・RCON パスワード** の 4 つを入力するだけでサーバーを追加できます。Cloudflare の画面で Secrets を設定する必要はありません。持っているサーバーの数だけ(最大 20 台)追加でき、画面上部のメニューで操作するサーバーを切り替えます。保存するとその場で接続を確認し、結果を表示します(つながらなくても保存はされるので、あとから直せます)。入力した RCON パスワードは暗号化して保存され、保存後は画面に表示されません。3 章の `RCON_URL` / `RCON_PASSWORD` で設定したサーバーは「既定サーバー」として一覧の先頭に出ます(画面からは変更できません)。

## 5. 動作確認

1. デプロイ完了画面に表示された URL(`https://wardogs-ops.<アカウント名>.workers.dev`)をブラウザで開きます。
2. ログイン画面が出たら、`ADMIN_PASSWORD` を入力します。「操作者名」は任意です(複数人で使う場合、操作ログに誰が操作したかを残すために入れます)。
3. 状態画面にサーバー名・マップ・人数が表示されれば成功です。
4. 「設定が足りません」という画面(`/setup`)が出た場合は、表示された名前の Secret を入れ直してください。
5. **本物の操作をする前に、操作ログに記録が残ることを確かめます。** 操作ログの画面を開いて今の行数を見てから、全体メッセージを 1 回送ります(プレイヤーに表示されます)。操作ログに行が 1 つ増えれば正常です。増えない場合は、操作ログが使えていないので [6.4](#64-操作ログd1が使えないと表示される) を確認してください。

表示されるエラーと対処:

| 表示 | 主な原因 | 対処 |
|---|---|---|
| RCON に接続できません | URL の間違い、ポートが開いていない、IP アドレスを指定している、DNS がプロキシ(オレンジの雲) | `RCON_URL`、4.1 のポート開放、4.3 を確認 |
| RCON の応答がありません | サーバーが停止中・再起動中、通信が遅い | 少し待って再読み込み |
| RCON の認証に失敗しました | パスワードが一致しない、AllowedHosts で拒否されている | ゲーム側と `RCON_PASSWORD` を同じ値に。4.2 を確認 |
| このサーバーでは使えない操作です | サーバーのバージョンにその機能が無い | ボタンは自動で無効になります |
| 操作ログが使えないため操作を止めています | D1 データベースが作られていない・初期化されていない | 6.4 を参照 |

## 6. 更新と困ったとき

### 6.1 更新する(方法 B: フォークの場合)

1. GitHub で自分のフォークを開き、**Sync fork** → **Update branch** を押します。
2. Cloudflare が自動で再デプロイします(Workers Builds)。Secrets や操作ログはそのまま残ります。

### 6.2 更新する(方法 A: ボタンの場合)

ボタンで作られたリポジトリは、元のリポジトリの「フォーク」にならない可能性があり、その場合は Sync fork が使えません(要確認)。そのときは、元のリポジトリの変更を自分のリポジトリに反映する作業が必要です。難しい場合は、方法 B で作り直すのが簡単です(Secrets は再入力が必要。操作ログは引き継げません)。

### 6.3 パスワードを変える

- **ログイン用(`ADMIN_PASSWORD`)**: Settings → Variables and Secrets で値を更新。全員がログアウトされるので、新しいパスワードでログインし直します。ログアウトは手元の Cookie を消すだけで、盗まれた Cookie は最長 12 時間有効です。共有の PC で使ったときは、ログアウトに加えてこのパスワード変更も行ってください。
  - **画面から追加したサーバー([4.4](#44-パネルにサーバーを追加する画面から))がある場合の注意**: `SESSION_SECRET` を設定していないと、`ADMIN_PASSWORD` を変えたときに、保存済みの RCON パスワードが読み出せなくなります(サーバー設定の画面に「パスワードの再入力が必要」と出るので、各サーバーの RCON パスワードを入れ直してください。表示名・ホスト名・ポートは残ります)。**`SESSION_SECRET` を設定しておけば、`ADMIN_PASSWORD` を変えても入れ直しは不要です**。サーバーを追加して使う場合は、`SESSION_SECRET`(ランダム 32 文字以上)の設定をおすすめします。ただし `SESSION_SECRET` そのものを変更・削除したときは入れ直しが必要です。また、`SESSION_SECRET` の新規設定と `ADMIN_PASSWORD` の変更は同時に行わず、`SESSION_SECRET` を設定してパネルの「サーバー設定」を一度開いてから `ADMIN_PASSWORD` を変えてください。
- **RCON 用(`RCON_PASSWORD`)**: 先にゲームサーバーの設定を変えて再起動し、すぐに Cloudflare 側の値も同じ値に更新します。その間はパネルから RCON に接続できません。パスワードが漏れた疑いがあるときは最優先で行ってください。画面から追加したサーバーは、Cloudflare 側ではなく「サーバー設定」の編集でパスワードを入れ直します。

### 6.4 操作ログ(D1)が使えないと表示される

- Cloudflare のダッシュボードの **Storage & Databases → D1** に `wardogs-ops-db` があるか確認します。
- 方法 B の場合は Deploy command が `pnpm run deploy` になっているか確認し、再デプロイします(データベースの初期化は deploy の中で行います)。
- それでも直らない場合、パネルは「読み取り専用」で動き続けます(状態・プレイヤー・BAN 一覧は見られます)。

### 6.5 その他

- ログイン画面で「しばらく待ってください」と出た: 同じ場所から 15 分に 5 回パスワードを間違えると 15 分ロックされます。
- 1 日の利用回数の上限(無料プランは 1 日 10 万リクエスト)に達すると、日本時間の朝 9 時まで止まります。画面は 30 秒ごとに自動更新され、裏に回したタブでは更新を止めるので、普通に使う分には上限に届きません。
- カスタムドメイン(例 `ops.example.com`)で使いたい場合は、`wrangler.jsonc` の `env` にある `gmkz`(作者の環境)のブロックをコピーしてキー名と `pattern` を自分のものに変え、`pnpm run deploy:env <キー名>` でデプロイします(Cloudflare でそのドメインを管理している必要があります)。この環境では `workers_dev` を `false` にしているので、入口はカスタムドメインだけになります。

## 開発者向け

- 設計: `docs/ARCHITECTURE.md`(構成・認証・要確認一覧)、`docs/API.md`(内部 API と RCON の対応)、`docs/PLAN.md`(企画)
- ローカル開発: `pnpm install` → `.dev.vars.example` を `.dev.vars` にコピーして値を入れる → `pnpm db:migrate:local` → `pnpm dev`
- ビルド: `pnpm build`。型チェック: `pnpm check`。単体テスト: `pnpm test`
- 手動デプロイ: `pnpm build` → `pnpm run deploy`(`wrangler deploy` の後に D1 のマイグレーションを適用)
- API の確認記録: `docs/API_TEST.md`

### ローカルで動かす(モック RCON を使う)

本物のゲームサーバーが無くても、付属のモック RCON(`scripts/mock-rcon.mjs`。架空のプレイヤーと BAN が入っている)で画面と API を試せます。

1. `pnpm install`
2. `.dev.vars.example` を `.dev.vars` にコピーし、次のように値を入れる(`.dev.vars` は `.gitignore` 済みでコミットされません)
   - `ADMIN_PASSWORD`: 16 文字以上の任意の文字列(ローカル用。本番と同じ値にしない)
   - `RCON_URL`: `http://localhost:7776`(`127.0.0.1` のような IP アドレスは使えない設計のため、`localhost` と書く)
   - `RCON_PASSWORD`: モックの既定値(`scripts/mock-rcon.mjs` の先頭に書いてある公開のダミー値。または、モックを起動するときに環境変数 `MOCK_RCON_PASSWORD` で指定した値)。`ADMIN_PASSWORD` とは別の値にする。**本物のサーバーの RCON パスワードはローカル開発で絶対に使わない**
3. `pnpm db:migrate:local`(ローカルの D1 に表を作る。初回だけ)
4. 端末を 2 つ開き、先に `pnpm mock:rcon`、次に `pnpm dev` を起動する(モックのポートは環境変数 `MOCK_RCON_PORT` で変えられる。既定 7776)
5. ブラウザで `pnpm dev` が表示した URL を開き、`ADMIN_PASSWORD` でログインする

補足:

- モックは自分の PC の中(ループバック)だけで待ち受けます。kick するとプレイヤー一覧から消え、ban すると BAN 一覧に増えます。モックを再起動すると元に戻ります
- 開発時のログイン Cookie は `wo_session`(`Secure` なし)、本番は `__Host-wo_session` です
- ローカルの D1 を以前の版の表で作ってしまった場合は、`.wrangler/state/v3/d1` を別名に移してから `pnpm db:migrate:local` をやり直してください
