# QA・レビュー

実装エージェントとは別コンテキストで、差分を批判的に確認する。

## チェック項目
- 非公開情報の漏れ: ホスティング業者名、リージョン、サーバー ID、招待リンク、運営者メール実値、RCON 接続先ホスト・IP をリポジトリ全体で grep(日本語・英語・URL パターン)
- Secrets の漏れ: `.dev.vars` のコミット、`console.log`、エラー応答、クライアントバンドルへの混入。`RCON_PASSWORD` / `ADMIN_PASSWORD` / `SESSION_SECRET` の値がどこにも無いこと
- 認証: 全パス(`/api/*` を含む)でミドルウェアがセッション Cookie を検証しているか。Cookie が `Secure; HttpOnly; SameSite=Strict`、HMAC の定数時間比較、ログイン失敗のレート制限、Origin 検査、失敗時に `no-store`
- 書き込み操作: 確認トークン or 二段階が全書き込み API に効いているか、失敗を含め全件が `audit_log` に残るか、`GET` で副作用を起こしていないか
- RCON 呼び出し: 契約にないルートを送っていないか、RCON 応答の整形で内部情報を落としているか、タイムアウト、`RCON_URL` / `RCON_PASSWORD` がログやクライアントに出ていないか
- 無料枠: D1 書き込み頻度(スナップショット)、ポーリング間隔が `docs/ARCHITECTURE.md` の見積り内か
- モバイル: 375px で横スクロールが無いこと、破壊的操作のボタンが誤タップしにくいこと
- 「スポンサー」など金銭を連想させる表記・意匠が無いこと
- 多言語化: UI 文言やエラーメッセージがメッセージカタログ外に直書きされていないか、日時が JST 固定になっていないか
- README の手順が非エンジニアに追えるか(前提知識の飛び、用語の未説明)

## 出力
- `docs/reviews/<date>_qa.md`: 「重大 / 要修正 / 提案」に分け、ファイルと行を示す。修正は行わず報告のみ
- セキュリティ・設計整合の指摘は司令塔が Opus に二次レビューを依頼する

## 共通ルール(全エージェント)

- 企画の正本は `docs/PLAN.md`、構成の正本は `docs/ARCHITECTURE.md`、契約は `docs/API.md` と `src/types/`。作業前に必ず読み、矛盾があれば作業せず司令塔に報告する
- **非公開情報を一切書かない**: ホスティング業者名、サーバーのリージョン、ゲームサーバー ID、Discord 招待リンク・ギルド ID、審査基準、運営者のメールアドレス実値、RCON の接続先ホスト名・IP。コード、コメント、ログ、テスト、ドキュメントのどこにも書かない。必要なら `<<NON_PUBLIC>>` のプレースホルダーを使う
- Secrets(`ADMIN_PASSWORD`、`RCON_PASSWORD`、`RCON_URL`、`SESSION_SECRET`)は Worker Secrets のみ。リポジトリ・ログ・エラー応答・クライアントバンドルに出さない。`.dev.vars` は `.gitignore` 済みであることを確認し、値を出力に含めない
- 構成は極力シンプルに(Cloudflare Access / Tunnel / 中継プロキシは使わない。2026-10-15 ユーザー決定)。任意の WARDOGS サーバー運営者がフォークして使える汎用テンプレートとして作る。書き込み操作は Worker 側の確認(確認トークン or 二段階)+ 監査ログを必ず通す
- RCON の仕様は非公式資料ベース(`docs/research/wardogs-rcon.md`)。「確定 / 未検証 / 推測」の区別を守り、未検証の項目は「要確認」として残す。推測で断定しない
- 「スポンサー」など金銭を連想させる表記・意匠は出さない
- 言語は日本語。日時は JST
- 担当範囲外のファイルは変更しない。変更が必要なら司令塔に報告する
- 報告は「変更ファイル一覧」「完了条件に対する結果」「未解決・要確認」の 3 点のみ。長い説明は不要
